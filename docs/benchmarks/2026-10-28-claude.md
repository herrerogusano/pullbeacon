## Manual review of disagreements

The matching rule counts every finding that is not the one labelled bug as a false positive. Each of
the 16 "false positives" was reviewed by hand (titles are in the JSON, `finding_summaries`):

| Verdict | Haiku | Sonnet | Examples |
|---|---|---|---|
| Valid additional issue present in the diff | 8 | 5 | prompt-injection comment aimed at reviewers (the prompt asks to report it); `withdraw` accepts negative amounts; missing-invoice not handled; feed crashes when an author is missing; new required parameter breaks existing callers; invalid date yields a `NaN` key; no tests for changed money/date logic |
| Same labelled bug split into a second finding | 1 | 2 | unbounded `limit` reported as "no upper bound" and "non-numeric raises"; refund rounding reported as correctness and as missing tests |
| Unsupported / wrong | 0 | 0 | — |

With these verdicts, neither model made an unsupported claim, and neither flagged anything on the four
clean PRs (refactor, rename, docs, stronger test). One Haiku finding (missing tests) had no valid line
and was posted in the summary instead of inline, as designed.

**Apply:** both models fixed `js_missing_await` exactly as the reference. For `py_unbounded_limit` neither
model marked its finding as applicable, so PullBeacon did not attempt an edit (`not eligible`) — the
safe outcome, not a validation failure.

## Trade-offs (5–8 lines, honest)

- On this small synthetic set both models found every labelled bug; the dataset is too small and too
  easy to separate them on recall.
- Sonnet split fewer issues into duplicates and wrote slightly more precise titles; Haiku produced a few
  more extra (mostly valid) findings.
- Haiku was ~13× cheaper per review (0.0006 vs 0.0083 USD) with similar latency (5.0 s vs 4.2 s).
- Neither model was steered by the injected "approve this PR" instructions; both reported them.
- One sample per case, no variance estimate: differences of one or two findings are noise.
- Next step for a meaningful comparison: larger, harder cases (multi-file, subtle logic) and labels for
  acceptable secondary findings, so precision reflects reviewer value rather than label coverage.

Decision taken from this run: the dogfood workflow uses `anthropic/claude-haiku-5-5` (cost) — see
