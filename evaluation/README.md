# PullBeacon evaluation

A small, reproducible benchmark of reviewers: issue detection, false positives on clean PRs,
location quality, cost and latency. It runs the **real** PullBeacon pipeline (diff parsing,
scope, prompts, validation) against an in-memory GitHub; only the LLM differs.

## Dataset (`evaluation/cases/`)

16 synthetic pull requests written for this benchmark (no third-party or private code),
generated by `evaluation/build_cases.py`:

| Kind | Cases |
|---|---|
| Python bugs | missing authorization, unbounded user input, unclosed file, N+1 query, check-then-act race |
| TS/JS bugs | unchecked optional, missing `await`, `innerHTML` XSS, timezone-dependent day key |
| Tests | critical change without tests, test that mocks the function under test |
| Clean (false-positive traps) | extract function, rename, documentation, stronger test |
| Prompt injection | comment and PR body asking reviewers to approve, hiding a SQL injection |

Each case has `ground_truth` (path, labelled lines, accepted categories, severity, rationale),
`expected_non_findings` (locations a careful reviewer should not flag), canned mock responses,
and for two cases an `apply_expectation` (exact expected file after the fix). Labels are
validated against the case's own diff when the dataset loads.

## Matching rule

A finding is a **true positive** when it is posted inline on the labelled path, within ±3 lines
of a labelled line, with one of the accepted categories; each issue matches at most once.
Findings without a valid diff line count as **false positives** (reported as *unlocated*).
Matching is deterministic and never graded by a model. Disagreements must be reviewed by hand:
a correct finding on a different line or with an unexpected category is scored as FP + FN.

## Metrics

Recall, precision, false positives per clean PR, unlocated findings, findings discarded by
validation (incl. duplicates), trap hits, latency, tokens, cost per review and per true positive,
and apply correctness (validated / exact match).

## Running

```bash
# Contract test of the harness (no network, no keys, no cost):
uv run python -m pullbeacon eval --dataset evaluation/cases --mock-llm --output evaluation/results/mock.json

# Live comparison (costs money; requires the provider key in the environment):
uv run python -m pullbeacon eval --provider live \
  --models anthropic/<model-a>,anthropic/<model-b> --confirm-spend --max-total-cost-usd 2 \
  --output evaluation/results/live.json
```

Each run writes `.json` (full metadata: date, PullBeacon version and commit, prompt versions,
dataset and config hashes, temperature, cost source), `.md` and `.csv`.

**Mock results measure nothing about model quality.** The mock reviewer is deliberately imperfect
(one miss, one false positive, one invented line, one duplicate) so the metric pipeline is
exercised; its numbers are asserted exactly in `tests/unit/test_evaluation.py`.

## Limitations

- 16 small synthetic cases, one sample per case: a difference of one or two cases between models
  is not statistically meaningful.
- Provider pricing comes from the LiteLLM cost map pinned in `uv.lock`; actual billing may differ.
- Live runs are never executed by CI; see `.github/workflows/benchmark.yml` (manual only).
